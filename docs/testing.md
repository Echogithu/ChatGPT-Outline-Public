# 章节锚点与消息替换修复：真实网站补验

## 目标与前置条件

在已登录的桌面 ChatGPT 测试账号中加载本次源码并刷新会话；记录浏览器版本、窗口尺寸、布局和版本号。使用不含个人信息的测试会话，至少有 10 轮问答、多个标题及两个同名章节。

自动化回归使用独立浏览器和模拟会话。真实网站的编辑、重新生成和虚拟历史行为可能随页面实现变化，以下项目不能仅用模拟页面代替。

## 步骤与预期

- [ ] 选择双侧布局，逐项点击含多个标题的回答；目标章节与点击文字一致。生成中的标题更新后再次点击，原章节不得跳到新增章节。
- [ ] 切换合并布局并重复章节点击；同名章节仍在对应回答内导航，不跳到其他回答。
- [ ] 滚动后立即编辑一个已有问题并提交，切换问题分支；目录只呈现当前分支，旧问题及已移除回答不残留。
- [ ] 滚动后重新生成回答；目录更新为当前显示的回答和标题，旧章节不残留。
- [ ] 已有含标题的回答后，发送下一轮问题，并在“正在生成”且正文尚空时检查目录；不得将上一条回答的章节重复列为新回答。正文出现后只新增本轮章节；同一轮重新生成时也应满足此条件。
- [ ] 点击重新加载目录后，在扫描期间继续生成或更新消息；扫描中及扫描结束后均不得同时保留已替换的旧问题/回答。完整扫描与首尾定位两种扫描都需检查。
- [ ] 在长会话上下来回滚动，完整扫描后点击已经离屏的问题和章节；历史目录不因虚拟卸载而消失，定位正确。
- [ ] 刷新并复用缓存，重新执行一次章节导航和分支切换；不同会话的目录不混入。
